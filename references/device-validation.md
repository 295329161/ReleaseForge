# 硬件与设备验收

仅在项目涉及固件、物理外设或实时音频时使用。以下来自 ESP32 桌面终端的实践；必须重新确认当前板卡，不能照搬 GPIO、串口号、SD 时钟、分区地址、亮度、音量或截图数量。

## 连接、数据与恢复

先查项目板级驱动、原理图/说明和既有诊断脚本，确认芯片、内存、USB/串口拓扑、下载与恢复路径。识别原生 USB 与独立串口桥是否为不同通道，核对控制线是否连到 BOOT/RESET。串口打开和关闭也可能改变 DTR/RTS 并复位设备，应优先复用经过验证的工具，同一串口仅一个读者。

测试前记录用户设置和存储基线。使用独立、有所有者标记的测试目录；遇到同名目录不覆盖。删除时核对标记及文件清单，只删除本次生成的内容，目录含额外用户文件则保留。不格式化用户介质、不擦除 NVS、不改 eFuse 来方便验证。更新固件须核对芯片、目标设备、分区、写入范围与恢复方法，避免把主机其他磁盘当作设备。

## 验证实际链路

- 音频：同时检查播放状态、解码进度、功放/输出路径以及可获得的回采或实际听音证据。“正在播放”不能证明出声。回采非零不能证明主观音质合格。
- 语音：分别验证连接、采集、上传、工具执行、回答完成、音频输出、退出与返回播放。文本诊断能验证会话和工具，但不能替代麦克风识别、真人打断、回声与不同声学条件。
- 搜索：确认真实检索结果进入最终回答，而不是仅回复“好的”。当前日期/新闻要检查来源时效；没有对应日期资料时正确说明未找到，不用旧新闻或模型记忆补成“今日结果”。
- 屏幕与按键：检查真实返回导航、确认/取消、短按/长按、消抖、熄屏/亮屏及重启后的保存设置。模拟点击是 UI 事件验证，不是全屏物理触摸验证；截图不证明背光状态。
- 存储：先验证测试文件本身正确，再验证播放/解码/文件操作。数据传输回读及重新连接后的校验更能排除主机缓存造成的假通过。
- 资源：记录空闲、活动和退出后的内部堆、DMA 连续空间、外部 RAM、任务/句柄等项目实际可观测指标。重复进入/退出关注持续增长或不释放；总空闲内存很多不代表关键连续内部内存足够。

跨模块回归应覆盖正在使用的资源交接，尤其是暂停后停止是否真正关闭文件、退出语音后音频时钟和功放是否恢复、卸载/挂载是否误改变其他引脚。底层“释放全部资源”接口可能影响未使用槽位，不能仅凭 API 名称判定没有副作用。

## USB 大容量存储项目的附加检查

仅当该功能存在时应用：

1. 本机文件系统和主机原始块访问必须独占。交接前停止使用文件的任务并释放句柄，退出后重新挂载和更新目录/播放索引。
2. 从 VID/PID、序列号、容量及拓扑识别目标；实际复制、改名、删除仅使用自有测试目录，并回读校验。
3. 已枚举、已挂载、空闲、USB suspend、文件系统卸载和安全弹出是不同状态，不能混为一谈。不要因短暂空闲或休眠强行交还本机存储。
4. 验证等待连接的超时与取消，以及电脑安全弹出后恢复本机访问和调试接口。软件禁止枚举的无主机模拟须明确标注，不能称作已经完成纯充电线物理测试。
5. 测试烧录恢复时先结束电脑写入并安全释放存储。保留 ROM/独立下载路径；不要为了证明可烧录，在主机写盘时强行复位。

不同操作系统的内置协议支持只能作为兼容性依据；没有在对应系统运行就记录未实测。写入中断电等破坏性试验需要合适的可丢弃介质和授权，不能用用户唯一的数据卡冒险。

## 实机收尾

确认测试目录清理、用户数据及设置保留、临时网页/测试会话按本次约定关闭、串口读者释放。需要交付已更新设备时，验证最终固件启动和关键状态，恢复约定的普通主页/模式；保存结果而非仅保存刷写成功日志。
