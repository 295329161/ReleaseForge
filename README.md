# ReleaseForge · 发布锻造台

**从全项目审查，到有证据的版本交付。**

ReleaseForge 是一个面向 Codex 的开源 skill，把代码审查、功能检验、逐页截图、修复回归、文件归档和版本发布串成完整流程。适用于 Web、桌面应用和嵌入式设备，尤其关注“页面显示成功，实际功能却没有完成”的问题。

*A reusable Codex skill for project-wide audits, functional verification, page screenshots, cleanup, and evidence-backed releases.*

[![License: MIT](https://img.shields.io/badge/License-MIT-76e4d4.svg)](LICENSE)

## 能做什么

- 从代码、路由、菜单和文档识别全部功能，建立逐项验收清单。
- 审查并修复真实缺陷，复测失败路径和受影响的共享功能。
- 保存每个页面及关键状态的真实截图，生成可浏览索引。
- 区分实际通过、失败、部分验证、未验证和未实现，不用截图或编译成功冒充验收通过。
- 整理当前源码、依赖、测试与文档，将历史实验和私有材料可追溯归档。
- 按指定版本交付源码、构建产物、验证记录与校验清单，保留旧标签和旧发布包。

硬件项目还会检查外设所有权、串口控制线、音频实际输出、存储交接、资源释放和烧录恢复。相关要求按项目适用，不绑定某块开发板、某个串口或固定版本号。

## 安装

将本仓库安装到 Codex 的个人 skills 目录。默认路径示例：

```bash
git clone https://github.com/295329161/ReleaseForge.git ~/.codex/skills/release-forge
```

如果设置了 `CODEX_HOME`，则安装到其 `skills/release-forge` 子目录。目标目录已存在时，请先检查原有内容，避免覆盖自定义修改。安装后在新的 Codex 会话中调用。

## 使用

在目标项目目录中告诉 Codex：

```text
使用 $release-forge，审查当前项目所有代码和功能，保存每个页面的截图，
修复并完成回归后整理文件和文档，满足验收条件时发布为 1.0.0。
```

版本号按项目需要替换。也可以指定实际环境、要保留的数据和发布目标：

```text
使用 $release-forge，为当前桌面应用做发布前全量验收。
目标版本是 2.1.0，保留用户配置和历史发布包。
保存所有页面及关键弹窗截图，完成后生成本地发布包。
```

该 skill 支持自动发现，也可以通过 `$release-forge` 明确调用。它是工作指令，不是独立执行程序；实际执行能力取决于当前 Codex 环境、项目工具链、设备与授权。

## 交付结果

优先沿用项目约定。常见结果包括：

- 逐项功能结果、缺陷修复和复测记录。
- `validation/<version>/` 下的截图、索引和验证证据。
- 更新后的使用、维护、安装与升级说明。
- 可追溯归档、源码版本、适用的构建产物及 SHA-256 清单。
- 明确的未验证项、已知限制和最终运行状态。

没有测试过的系统或物理链路会如实标注。必需验收条件不满足时，不会把候选包宣称为正式通过。没有指定外部发布目标时，不会擅自上传到公共站点；已有明确授权则继续完成对应工作。

## 文件结构

```text

references/device-validation.md    硬件、音频、存储与 USB 专项检查
references/evidence-release.md     验收证据、归档与发布包约定
```

## 设计原则

真实运行结果优先于表面状态；保护现有行为和用户数据；修复后检验相邻功能；清理前确认用途并归档；最终源码、验证证据和发布产物保持对应。

本项目提炼自真实设备项目的验收实践，但不携带原项目源码、设备标识、个人配置或私有日志。它不能替代特定领域的认证，也不保证在缺少硬件或服务的环境中完成所有实测。

## 贡献

欢迎通过 Issue 描述实际失效场景，或提交聚焦的 PR。请说明触发条件、当前行为及期望结果，避免上传密钥、用户数据、私有日志或未脱敏截图。流程改进应有具体场景依据，避免增加与普通项目无关的强制步骤。
